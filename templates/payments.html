Payment lifecycle this panel respects

  1. Vendor initiates payment in the vendor app

    Amount = agreed item amount + commission (proposed basis).

  2. Gateway returns a result to the backend

    Webhook / server-to-server verification. No client-side step.

  3. Backend stores the transaction status

    pending → successful / failed / refunded. The admin panel only displays it.

  4. Invoice generated on success

    Never generated for failed or pending payments.

What admins cannot do here

  • Mark a gateway payment successful
  • Edit a gateway reference or timestamp
  • Issue an invoice before success
  • Contact the gateway, then record the outcome in the refund workflow
Integration notes

Backend integration point

POST /admin/payments/{id}/notes Statuses arrive from the payment gateway via the backend. Any manual reconciliation must be stored as a separate, audited note — not as a status change.
